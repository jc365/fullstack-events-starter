# Security Audit Report — Castant

**Date:** 2026-07-25
**Scope:** Backend (Express + Prisma + SQLite), Frontend (React + Vite)
**Auditor:** opencode

---

## Executive Summary

The application has **3 critical**, **6 high**, **5 medium**, and **3 low** severity findings. The most urgent issues are: a hardcoded JWT secret fallback, authorization bypasses on destructive endpoints, and JWT tokens leaked in logs.

| Severity | Count |
|----------|-------|
| Critical | 3 |
| High | 6 |
| Medium | 5 |
| Low | 3 |

---

## CRITICAL Findings

### C1: JWT Secret Hardcoded Fallback

**Severity**: Critical
**Location**: `backend/src/infrastructure/middleware/auth.ts:9`
**Description**: If `JWT_SECRET` env var is not set, the app falls back to `'default-secret'`, which is publicly visible in source code.
**Impact**: Anyone can forge valid JWT tokens and impersonate any user.
**Fix**:
```typescript
const JWT_SECRET = process.env.JWT_SECRET;
if (!JWT_SECRET) {
  throw new Error('JWT_SECRET environment variable is required');
}
```

---

### C2: JWT Token Leaked in Logs

**Severity**: Critical
**Location**: `backend/src/infrastructure/middleware/auth.ts:19`
**Description**: `console.log(authHeader)` logs the full `Authorization: Bearer <token>` header to stdout on every authenticated request.
**Impact**: JWT tokens are exposed in log files, CI/CD output, and container logs. Attackers with log access can steal sessions.
**Fix**: Remove the `console.log(authHeader)` line entirely.

---

### C3: `.env` Files Not in `.gitignore`

**Severity**: Critical
**Location**: `.gitignore` (root)
**Description**: The `.gitignore` does not exclude `.env` files. The `backend/.env` contains `JWT_SECRET=tu-secreto-super-seguro`.
**Impact**: Secrets can be committed to version control and exposed to anyone with repo access.
**Fix**: Add `.env*` to `.gitignore`:
```gitignore
# Environment variables
.env
.env.local
.env.*.local
```

## HIGH Findings

### H1: Authorization Bypass on Destructive Endpoints

**Severity**: High
**Location**: `backend/src/infrastructure/api/v1/routes.ts` — multiple endpoints
**Description**: Several endpoints perform destructive operations without verifying the authenticated user's role or ownership:

| Endpoint | Missing Check |
|----------|---------------|
| `DELETE /users/:id` | No check if user is deleting their own account |
| `PUT /castings/:id` | No check if user is a director of the casting |
| `DELETE /castings/:id` | No check if user is a director of the casting |
| `DELETE /rounds/:id` | No check if user is a director of the casting |
| `DELETE /submissions/:id` | No check if user owns the submission |
| `POST /rounds/participants` | No check if user is a director |

**Impact**: Any authenticated user can delete any other user's casting, round, or submission.
**Fix**: Add ownership/role checks similar to `ReviewSubmissionUseCase`:
```typescript
// Example for DELETE /castings/:id
const casting = await castingRepository.findById(id);
const isDirector = casting.directorIds.some(id => id === req.user?.id);
if (!isDirector) {
  res.status(403).json({ error: 'Not authorized' });
  return;
}
```

---

### H2: JWT Stored in localStorage (XSS Vulnerable)

**Severity**: High
**Location**: `frontend/src/api/client.ts:13`, `frontend/src/components/Layout.tsx`
**Description**: JWT tokens are stored in `localStorage`, which is accessible to any JavaScript running on the page.
**Impact**: XSS attacks can steal JWT tokens. If an attacker injects script, they can read `localStorage.getItem('token')` and hijack sessions.
**Fix**: Use httpOnly cookies instead. Configure the backend to set tokens as:
```typescript
res.cookie('token', token, {
  httpOnly: true,
  secure: true,
  sameSite: 'strict',
  maxAge: 86400000
});
```

---

### H3: No CORS Restrictions

**Severity**: High
**Location**: `backend/src/index.ts:21`
**Description**: `app.use(cors())` enables CORS with no restrictions (allows all origins, methods, and headers).
**Impact**: Any website can make authenticated API requests on behalf of logged-in users (CSRF-like attacks).
**Fix**:
```typescript
app.use(cors({
  origin: process.env.CORS_ORIGIN || 'http://localhost:5173',
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
}));
```

---

### H4: No Rate Limiting

**Severity**: High
**Location**: `backend/src/index.ts`
**Description**: No rate limiting middleware is configured. The login endpoint (`POST /auth/login`) is particularly vulnerable.
**Impact**: Brute-force attacks on login, API abuse, denial of service.
**Fix**: Install and configure `express-rate-limit`:
```typescript
import rateLimit from 'express-rate-limit';

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 10, // 10 attempts
  message: 'Too many login attempts',
});
router.post('/auth/login', loginLimiter, ...);
```

---

### H5: No Security Headers (Helmet)

**Severity**: High
**Location**: `backend/src/index.ts`
**Description**: No `helmet` middleware. Missing security headers: `X-Content-Type-Options`, `X-Frame-Options`, `Strict-Transport-Security`, etc.
**Impact**: Vulnerable to clickjacking, MIME sniffing, and other browser-based attacks.
**Fix**:
```typescript
import helmet from 'helmet';
app.use(helmet());
```

---

### H6: Weak JWT Secret in `.env`

**Severity**: High
**Location**: `backend/.env:3`
**Description**: `JWT_SECRET=tu-secreto-super-seguro` is a weak, human-readable string.
**Impact**: Easily guessable secrets allow token forgery.
**Fix**: Generate a strong secret:
```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

## MEDIUM Findings

### M1: Request Bodies Logged (Sensitive Data Exposure)

**Severity**: Medium
**Location**: `backend/src/index.ts:48`
**Description**: pino-http serializer logs `req.body` on every request, including passwords and tokens.
**Impact**: Passwords, tokens, and PII appear in log files.
**Fix**: Exclude sensitive fields from logging:
```typescript
serializers: {
  req: (req) => ({
    method: req.method,
    url: req.url,
    // Don't log body — may contain passwords/tokens
  }),
}
```

---

### M2: Demo Mode Should Be Disabled in Production

**Severity**: Medium
**Location**: `backend/.env:2`, `backend/src/application/use-cases/LoginUseCase.ts:12`
**Description**: `DEMO_MODE=true` allows passwordless login via `xUserId`. If accidentally enabled in production, anyone can log in as any role.
**Impact**: Complete authentication bypass if enabled in production.
**Fix**: Add startup check:
```typescript
if (process.env.NODE_ENV === 'production' && process.env.DEMO_MODE === 'true') {
  throw new Error('DEMO_MODE must not be enabled in production');
}
```

---

### M3: Weak Default Password for Auto-Created Users

**Severity**: Medium
**Location**: `backend/src/application/use-cases/CreateCastingUseCase.ts:47`, `ManageRoundParticipantsUseCase.ts:123`
**Description**: Auto-created users get password `'changeme'` (hardcoded).
**Impact**: Known default passwords allow account takeover.
**Fix**: Generate random passwords:
```typescript
const randomPassword = crypto.randomBytes(16).toString('hex');
const defaultPassword = await this.hashService.hash(randomPassword);
```

---

### M4: Debug Log Level Default

**Severity**: Medium
**Location**: `backend/src/infrastructure/logging/logger.ts:11`
**Description**: Default log level is `'debug'` when `NODE_ENV` is not set.
**Impact**: Excessive logging may expose sensitive data in production.
**Fix**: Default to `'info'` in production:
```typescript
level: process.env.LOG_LEVEL || (isDev ? 'debug' : 'info'),
```

---

### M5: No Input Length Validation

**Severity**: Medium
**Location**: `backend/src/infrastructure/api/v1/routes.ts` — multiple endpoints
**Description**: No maximum length validation on text inputs (title, description, name, email).
**Impact**: Potential DoS via extremely large payloads, database bloat.
**Fix**: Add validation in use cases or route handlers:
```typescript
if (title && title.length > 200) {
  res.status(400).json({ error: 'Title must be 200 characters or less' });
  return;
}
```

## LOW Findings

### L1: No HTTPS Enforcement

**Severity**: Low
**Location**: `backend/src/index.ts`
**Description**: No HTTPS redirect middleware. Production deployments must configure this at the infrastructure level (reverse proxy, load balancer).
**Fix**: Document that HTTPS must be terminated at the reverse proxy (nginx/ALB).

---

### L2: No CSRF Protection

**Severity**: Low
**Location**: `backend/src/index.ts`
**Description**: No CSRF tokens. The app relies on JWT Bearer tokens which are somewhat resistant to CSRF, but cookie-based auth would need CSRF protection.
**Fix**: If switching to cookie-based auth, add `csurf` middleware.

---

### L3: File Extension from User Input

**Severity**: Low
**Location**: `backend/src/infrastructure/storage/videoUpload.ts:35`
**Description**: `path.extname(file.originalname)` uses the user-provided filename extension. While multer's fileFilter checks MIME types, the extension is not sanitized.
**Impact**: Minimal since the filename is random (`Date.now()-random.ext`), but the extension could be misleading.
**Fix**: Map MIME types to fixed extensions:
```typescript
const mimeToExt: Record<string, string> = {
  'video/mp4': '.mp4',
  'video/webm': '.webm',
  // ...
};
const ext = mimeToExt[file.mimetype] || '.mp4';
```

## Positive Findings

- **Password hashing**: bcrypt with 10 salt rounds (good)
- **SQL injection**: Prisma ORM handles parameterization (safe)
- **XSS**: React escapes output by default (safe)
- **File upload**: MIME type whitelist + size limit (good)
- **Token expiry**: JWT expires in 24h (acceptable)
- **Authorization on review**: `ReviewSubmissionUseCase` properly checks director role
